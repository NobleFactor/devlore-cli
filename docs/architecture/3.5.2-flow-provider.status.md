## Document Discrepancies (design vs. current code)

- **Choose was a value-picker; now mid-rebuild.** The old `flow.Choose` iterated `defaultCase any, cases ...Case` with an
  `isTruthy` loop over eagerly-computed values — gutted 2026-07-01. `flow.Choose` is now execute-the-graph and `Case` is
  `{When, Then op.Subgraph}`, but `plan.Provider.Case` still builds it with `any` args (build red) and `ChoosePlanner`
  still delegates to the childless `planSubgraphFromParams`. The design is a **conditional-edge binary decision tree**
  the method just executes — see step 10; the remaining work is `op.Edge.Guard` (`GuardResult`) + guard-stamped
  receipts + `validateGuardedEdges` and ordering-edge cycle validation (malformed documents rejected at load) + the
  decision-tree traversal + `plan.case`/`ChoosePlanner` wiring. (`isTruthy` already adopted the settled
  Python/Starlark truth semantics, 2026-07-01: empty containers, zero-value structs, and typed nils are falsy.)
- **`Case` shape.** Today `Case{When any, Then any}` carries values; the design pairs a `when`-subgraph with a
  `then`-subgraph.
- **WaitUntil.** A lambda-polling stub with no behavioral tests; the design re-evaluates a predicate **subgraph** each
  poll (step 12).
- **Delegation.** `Gather`/`Choose` share Subgraph's `walkSubgraphChildren` directly rather than calling the `Subgraph`
  method (see the design doc's §10.1) — an intentional interim until a child-activation affordance exists.
