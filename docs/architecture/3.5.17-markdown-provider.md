## Thesis

A `markdown` provider gives Starlark one parser for markdown documents: read a document into a tree, walk it, and
render it to HTML, to the terminal, and back to markdown. It is a framework provider, shared by every program, not one
of star's own.

## Who needs it

| Consumer | Need |
| --- | --- |
| noblefactor-ops#319, star gh's schedule and thread tables | tables read from documents on disk; issue bodies are read from GitHub's own rendering, `bodyHTML` |
| #932, `star lint frontmatter`; `star lint markdown` | frontmatter and structure from one parse, with positions for findings and `--fix` |
| #1063, the knowledge extension | the registry's documents read and written by structure |

## Decided

Recorded on #1100.

- **goldmark v1, at v1.8.6.** One goldmark, the line glamour uses. Ruled 2026-10-20: "Since Glamour is behind, we
  cannot use the latest and greatest goldmark. We must use the version that works with glamour." goldmark v1.8 gives
  every node a start position. goldmark v2 waits until glamour moves to it.
- **The terminal through glamour v2,** on the same goldmark, as `--output terminal` renders today; the Charm stack moves
  to v2 in #1101.

## To design

- The API surface: what Starlark calls, and what a parsed document looks like to it.
- Frontmatter: [abhinav/goldmark-frontmatter](https://github.com/abhinav/goldmark-frontmatter) (YAML and TOML,
  maintained) or [goldmark-meta](https://github.com/yuin/goldmark-meta) v1.1.0 (YAML, 2022).
- Writing markdown back: [teekennedy/goldmark-markdown](https://github.com/teekennedy/goldmark-markdown) v0.5.1, to be
  evaluated, including how it treats link reference definitions, a node type new in goldmark v1.8.
- HTML code highlighting: nothing exists on goldmark v1; needed only if HTML output highlights code.
- Role and claims: module, action, or both; which methods are deterministic.
