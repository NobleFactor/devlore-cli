## Settled

All ruled by the owner on 2026-10-02.

- [x] **Binding is the model**: an activity binds one `fsroot.Binding` for each tree it touches; the scope, the
  layer and the lore package declare which named roots they use and in what role.
- [x] **The type is `fsroot.Binding`**, beside `op.Binding`.
- [x] **The activity is the lifecycle operation**, one per writ scope; one lore install.
- [x] **The role is declared where a root is used**, not fixed on the root.
- [x] **The root travels with the data**: the pre-flight seam binds by name; `RuntimeEnvironment.Root()` goes.
- [x] **star binds a path when it is created**; an absolute path no binding holds is refused.
- [x] **star's defaults**, reserved: `work`, `repo`, `config`, `data`, `state`, `cache`, `bin`, `scratch`; roots are
  added in `extension.yaml`, `star.roots`, or `--root`.
- [x] **The vocabulary**: scope names for targets, `<layer>:<scope>` for layer trees, `package` for lore, `@name/rel`
  in plan space.
- [x] **The XDG trees are reserved bindings in every program**, `bin` among them.

## Discrepancies (design vs. current code)

- `op.RuntimeEnvironment` holds one root, and about 80 call sites read `Root()`.
- `op.RootBinder` binds every resource to the one root (`pkg/op/graph_executor.go:1284`).
- writ widens its runs to `fsroot.CommonAncestor` of the trees they touch: deploy, upgrade, adopt, layer
  registration.
- lore and star anchor at the working directory; devlore's own trees open through `cli.OpenTree`.
- writ's readback and `workflow verify` anchor at `string(filepath.Separator)`, drive-relative on Windows.
- Plan space refuses `@name/...`, reserving it for this design.
