## Thesis

The function provider (`pkg/op/provider/function`, `op.RoleAction`, `+devlore:access=planned`) makes Starlark
functions **first-class graph values**: a function or lambda passes through planning as a content-addressed
`*function.Resource` and is invoked at dispatch by the one action, `function.call` — the leaf every combinator's
lambda body desugars to (phase-8 step 10).

Design points:

1. **A function is extracted into a self-contained synthetic source file.** Captured closure values are rendered as
   Starlark literals (`formatLiteral` over none / bool / int / float / string / list / dict / tuple / struct,
   nested), so the archived source is executable without its original environment.
2. **Identity is the source; the pack carries both forms.** The URI is `sha256:<hex>` over the synthesized source
   bytes; the on-disk artifact is a **function pack** — source section + compiled-bytecode section behind a magic
   header — stored at mem's sharded CAS path and archived to the `op.RecoverySite`. The compiled form and compiler
   version are **caches, not identity**: never persisted through JSON/YAML; `Resource.Init` repopulates them from
   the pack (mmap fast path), and a **compiler version skew falls back to recompiling from source** — the source is
   the durable truth, matching the independent source-vs-bytecode digest ruling.
3. **`Call` evaluates at dispatch**, `Call(callable, args, kwargs)` — invocation runs through the session's
   Starlark machinery, and the result flows as the node's output like any other action result.

## API surface

```go
func (p *Provider) Call(callable *Resource, args []any, kwargs map[string]any) (any, error) // function.call(callable, *args, **kwargs)
```
