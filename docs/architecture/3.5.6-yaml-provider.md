## Thesis

The yaml provider (`pkg/op/provider/yaml`, `op.RoleModule|op.RoleAction`) mirrors the json
provider for YAML text: `Decode` / `Encode` value transforms plus `Parse` → the content-addressed `yaml.Resource`.

The load-bearing design point: **`yaml.Resource` is an alternative input rendering of `json.Resource`.** YAML input
is parsed to a Go value, then re-marshaled **via `encoding/json`** to the same canonical byte form — so two
semantically equal documents, *whether YAML or JSON*, regardless of indentation, key order, comments, or flow vs
block style, produce **identical hashes** (`TestNewResource_YAMLAndJSONAgreeOnHash`). The URI scheme stays `yaml:`
so the catalog distinguishes the resource types even when the underlying digests collide. `Parse` is content-keyed
with producer stamping, exactly as json's.

**`yaml.Resource` is a sealed interface**: an exported interface embedding `op.Resource`, sealed by an unexported method
it declares itself, over an unexported struct in the provider's package. Nothing outside the `yaml` package can build one, which
is what the resource model's guarantees rest on ([4.3](4.3-resource-registration.md) §5 is the contract;
[4](4-resource-management.md) §9 item 19 is what it buys).

## API surface

```go
func (p *Provider) Decode(data string) (any, error)                 // yaml.decode(data)
func (p *Provider) Encode(value any) (string, error)                // yaml.encode(value)
func (p *Provider) Parse(activationRecord *op.ActivationRecord,
	data string) (*Resource, error)                                 // yaml.parse(data)
```

No `EncodeIndent` — YAML output is block-styled by the encoder. Canonicalization caveats inherit from
`json.Resource` (within-Go determinism, float64 precision, UTF-8 key sort).
