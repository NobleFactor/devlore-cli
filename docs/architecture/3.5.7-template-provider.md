## Thesis

The template provider (`pkg/op/provider/template`, `op.RoleModule|op.RoleAction`) is pure
content transformation: input content → Go `text/template` expansion → output content. **No filesystem access** — a
deployment pipeline composes it with the file provider (render, then `file.write_*`).

The one deliberate design point is the render-time function map's **`Env`** function: its values resolve **at
dispatch time on the machine rendering the template**, never at plan time. Graphs are transportable and the store
keeps every plan — resolving at plan time would embed environmental state, potentially secrets, into durable graph
documents. The same plan therefore renders differently under different environments *by declaration*.

Its source is the **runtime variable space**, not the process environment (ruled 2026-08-25,
[#683](https://github.com/NobleFactor/devlore-cli/issues/683)): a template reads only what the run declares, the way
`make` does. A value reaches the variable space through the variables family, `--variable NAME=value`,
`<PREFIX>_VARIABLE_<NAME>` or `<program>.variable.<NAME>`
([configuration.md § Variables](configuration.md#variables--supplemental),
[#1023](https://github.com/NobleFactor/devlore-cli/issues/1023)). Whether the function keeps the name `Env` is
#683's to settle.

## API surface

```go
func (p *Provider) RenderBytes(content []byte, data map[string]any) ([]byte, error) // template.render_bytes(content, data)
func (p *Provider) RenderText(content string, data map[string]any) (string, error)  // template.render_text(content, data)
```

Both parse `content` as a Go `text/template` with the render function map and execute it over `data`; parse and
execute errors are wrapped and returned. `data` may be nil.
