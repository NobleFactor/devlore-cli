## Thesis

The encryption provider (`pkg/op/provider/encryption`, `op.RoleAction`, `+devlore:access=planned`) is SOPS-backed
file cryptography: two compensable pairs, `encryption.decrypt_sops_file` and `encryption.encrypt_file`, each taking
a `*file.Regular` source and a destination path and producing a `*file.Regular` plus the provider's own `*Receipt`.

Design points:

1. **The file taxonomy is the contract surface.** Sources and products are `*file.Regular` — the sealed taxonomy's
   regular-file variant ([3.5.4](3.5.4-file-provider.md)) — so plan-time kind assertions apply to crypto
   operations exactly as to writes.
2. **SOPS custody lives in `pkg/sops`.** The provider holds a `sops.Client` (decryption) and `sops.Encrypter`;
   ciphersuite and key custody are the sops package's concern, not the graph's.
3. **Compensation removes the product.** `CompensateDecryptSopsFile` removes the decrypted plaintext file — the
   receipt records the destination; undo deletes it (tolerating an already-missing file). `Receipt.RestoreEncoded`
   resolves through the catalog (phase-8 step 44).
4. **Known seam gap (recorded, phase-8 step 49):** the provider's write path bypasses the file provider's
   conflict-policy write seam; `writ deploy`'s pre-flight still gates occupied targets.

```go
func (p *Provider) DecryptSopsFile(activationRecord *op.ActivationRecord, source *file.Regular,
	destinationPath string) (*file.Regular, *Receipt, error)  // encryption.decrypt_sops_file(source, destination_path)
func (p *Provider) CompensateDecryptSopsFile(activationRecord *op.ActivationRecord, receipt *Receipt) error

	destinationPath string) (*file.Regular, *Receipt, error)  // encryption.encrypt_file(source, destination_path)
func (p *Provider) CompensateEncryptFile(activationRecord *op.ActivationRecord, receipt *Receipt) error
```
