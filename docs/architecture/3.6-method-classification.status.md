# Method Classification — Pure, Query, Action — Status

**Document:** [3.6-method-classification.md](3.6-method-classification.md)
**State:** Design draft (2026-08-19). Establishes a per-method classification from which namespace placement and
hermeticity both derive, replacing the retired provider-level access directive. No implementation.

## Completion

- [x] **`both` diagnosed as the tell** — it does not describe a provider, it says the provider's methods are not
  all the same kind. `file` shown as three kinds under one annotation.
- [x] Three kinds defined — pure, query, action — with **namespace placement and hermeticity both derived** from
  the one property rather than annotated separately.
- [x] The mutation hole shown to close **by construction**: an action changes the world, so it is a graph node,
  so it carries a receipt. Unrecorded mutation during planning becomes inexpressible rather than filtered.
- [x] **Attribution ruled optional**, on the argument that mandatory attribution does not reduce the only
  dangerous error (a false `pure` claim) and manufactures it where none was needed — `platform.Hostname()`
  defaults correctly to query when nobody annotates it.
- [x] Default ruled to be `query`, which fails closed.
- [x] **Action tier shown inferable for free** from a `*Receipt` return, which the repository already enforces
  through its Fallible / Actions / Compensable delineators.
- [x] **Pure/query shown not inferable** from signatures, in the dangerous direction: `Join(...) string` and
  `Hostname() string` are indistinguishable because a signature encodes failure and undo, never provenance.
- [x] The call-graph check identified as necessary under **any** scheme, so not a differentiator.
- [x] Optional attribution's ambiguity (silence means considered-or-forgotten) resolved by having codegen
  **emit** the derived classification into the generated file, so it is reviewable in a diff.
- [x] Runtime policy named as the second, irreducible dimension, with the three runtimes' policies sketched.
- [x] Two providers identified that the scheme cannot classify — `template` and `plan`.
- [x] **Expressibility added as a second derived property (§4a, 2026-08-25).** Classification answers what a
  method does to the world; it does not answer whether an author can call it. Every resource currently
  publishes methods that resolve and then fail at parameter binding — `can_convert_from`, `convert_to`,
  `init` — because their parameters are `reflect.Type` and `*starlark.Thread`. A framework callback has no
  effects, so it classifies as `query` and stays announced: the axes are independent. Ruled derived rather
  than annotated, answered by `op.Convert`'s cascade, and emitted like the classification.

## Open

- [ ] **Does `query` belong in immediate scope at all?** Excluding it is simpler than a policy dimension, at the
  cost of `file.exists` during planning.
- [ ] **`devlore-test`'s policy** — its fixtures exercise both modes deliberately.
- [x] **Migration** — resolved 2026-08-25: the provider-level access directive was removed in one pass, no shim.
- [ ] **Does the call-graph check gate the build or warn?** Gating on an analysis interfaces can defeat risks
  blocking on a false positive; warning risks being ignored.
- [ ] **`template`** — remove `Env` from the function map, or make the map per-runtime configurable.
- [ ] **`plan`** — admit it to planning on separate grounds, or move `LoadDefinition` out of the provider.

## Depends on

[#563](https://github.com/NobleFactor/devlore-cli/issues/563) is the other half. Classification is a fact about
a method; which kinds an evaluation admits is a policy of the runtime. Neither dimension can express the other,
and #563's per-runtime module selection is where the policy lives.
