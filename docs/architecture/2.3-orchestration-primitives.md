Flow actions — Subgraph, Choose, Gather, WaitUntil, Complete, Degraded, Failed — are visible runtime operations, not
engine internals. Each is a unit in the graph, recorded in dry-run output and preserved in the trace. The executor
does not distinguish "resource actions" from "flow actions" at dispatch — both are bound actions on units.

## Design Principle

**The graph is self-contained.** No hidden runtime queries. Every decision the executor makes is rooted in a graph
unit whose inputs and outputs are traceable. The plan shows what will happen and why; the trace shows what happened
and why.

| Runtime behavior | Flow action |
|---|---|
| Execute a nested scope | **`flow.subgraph`** |
| Take a planner-built branch | **`flow.choose`** |
| Iterate over items | **`flow.gather`** |
| Wait for a condition | **`flow.wait_until`** |
| End the run early, successfully | **`flow.complete`** |
| Absorb a failure, continue degraded | **`flow.degraded`** |
| Assert a failure | **`flow.failed`** |

Privilege elevation is not a flow action: it is a per-unit **policy** resolved at plan time
([2.6](2.6-execution-policies.md)) fulfilled by the elevation provider ([6.1](6.1-privilege-elevation.md)).

## The One Rule — a subgraph is an executor

**Every subgraph executes via its own executor, and that executor owns the subgraph's recovery stack** — together
with the subgraph's variable scope, pause state, trace, and catalog scope. There is one rule, applied recursively
down the subgraph tree (landed: phase-8 step 31).

- **There are no special "combinators."** `Gather`, `Choose`, `WaitUntil`, and `Subgraph` are not distinct kinds of
  thing — each *is* a subgraph, and each dispatch gets its own child executor. The non-`Subgraph` combinators are
  **quantifiers over the one base case**, differing only in how many body dispatches they make: `Choose` exactly one,
  `Gather` one per item, `WaitUntil` one or more (until truthy or timeout).

- **`Choose` does NOT select a branch.** `ChoosePlanner` constructs `Choose` as a single subgraph with the branches
  built **into the graph** at plan time. At runtime the **graph** selects which branch executes; `Choose` runs that
  one planner-built subgraph and merely **receives the result**. There is no runtime case-selection in `Choose`.

- **The executor owns the stack; the combinator returns it.** The per-dispatch executor creates the stack and
  supplies it as `activation.Stack`; a combinator's forward method never mints one. Every combinator returns
  `(any, *op.RecoveryStack, error)` — the result plus that same stack as its receipt-side compensator — and keeps its
  compensate companion (`CompensateSubgraph` / `CompensateChoose` / `CompensateGather` / `CompensateWaitUntil`, each
  `(activation, stack) error`). `Gather` returns **one** stack carrying one *stamped substack per iteration* in index
  order — the "slice of stacks" shape predating step 42 is gone.

- **The per-subgraph stacks chain — up for resolution, down for unwind.** The stacks form one tree linked two ways.
  Up: `ResultByUnitID` walks the ancestor chain so a promise resolves against whatever ancestor stack holds the
  producer's receipt. Down: a completed subgraph's stack is pushed **directly** onto its parent as a nested entry,
  **stamped** with the subgraph's unit identity and outcome (`Stamp(unitID, result, err)`; phase-8 step 42 slice 3a),
  and `Unwind` recurses into it. The nesting is durable — the trace serializes the tree — while the parent pointer is
  transient, re-derived on load; that split is what makes resume's promise resolution and skip-completed work.

- **Resume is a side-effect-free pseudo replay** (landed: step 31 arc). Restarting a paused run re-dispatches
  *nothing* the trace already records — no provider call, no compensation. `Run` re-descends the graph from the
  root; a unit with a successful receipt is skipped (cached result returned; a completed subgraph's whole subtree
  pruned), and the walk descends only the unfinished spine to the frontier. The descent **adopts each subgraph's
  restored child stack** and **re-resolves the per-subgraph variable frames** (the one piece of state the trace does
  not carry — pure recomputation against the restored stacks). The call stack is gone (`ErrPaused` unwound it back to
  `Run`), so resume rebuilds position by re-descending, not jumping.

- **The saga boundary is per-subgraph and retry-gated.** Each subgraph executor is a saga boundary, and the boundary
  is *maintained* — rollback is a per-boundary unwind that propagates outward, never a single root-level sweep. A
  boundary exhausts its retry policy **before** rollback continues up; the failure then reaches the next outer
  boundary, which applies *its own* policy before unwinding and propagating further. Because the boundary is atomic,
  each failed attempt first unwinds to the boundary's entry precondition before the next retry — re-running completed
  children without undoing them would double-apply non-idempotent work, so there is no no-undo retry. The tri-state
  retry policy (explicit / structural-boundary default with full jitter / none) landed as step 35 and is owned by
  [2.6](2.6-execution-policies.md).

**Why this is the model.** With per-subgraph executors owning their stacks, pause/resume, skip-already-completed, and
catalog capture/restore are one recursive rule — the serialized trace is a tree of sub-traces mirroring the subgraph
tree — instead of per-combinator special handling.

## The Combinators

All four share the dispatch shape `(activation *op.ActivationRecord, …) (any, *op.RecoveryStack, error)` and guard on
`activation.Graph` (`pkg/op/provider/flow/provider.go`).

### `flow.subgraph` — the base case

Walks the subgraph's children under the per-dispatch executor: toposorted order, promise resolution against the
chained stacks, each completed child pushed onto `activation.Stack`. Everything else is this, quantified.

### `flow.choose` — the planner-built branch

`ChoosePlanner` builds the branch structure into the graph at plan time; the dispatch runs the one planner-built body
subgraph and receives its result. `activation.Stack` carries whatever the branch ran; `CompensateChoose` unwinds it.

### `flow.gather` — concurrent iteration

`Gather(activation, items, kwargs)` runs the body subgraph **once per item, concurrently** up to `limit`
(goroutine-per-item throttled by a semaphore). Each iteration walks the body on its **own** child stack with its own
frame binding `item` — the body is one materialized template dispatched N times, never duplicated per iteration.
Stamping and nesting run on the dispatching goroutine in index order, so `activation.Stack` stays single-writer.
Bodies read the iteration value via `plan.variable("item")` and project record fields via `plan.item("field")`
(resolve-time field projection; phase-8 step 45).

The concurrency contract is the plan author's: items that feed file operations must be **unique**. Two iterations
producing the same resource is a plan conflict; two iterations modifying the same path is a race — both by design;
fix the plan, not the framework.

### `flow.wait_until` — poll until truthy

`WaitUntil(activation, timeout, interval, kwargs)` re-dispatches the body subgraph each poll until its result is
truthy or `timeout` elapses. Each poll runs on a scratch child stack; falsy polls are dropped unrecorded; the truthy
run is stamped with the unit's identity and nested. Timeout fails with the last observed value in the error.

## Terminals and Error Actions

The run's terminal grid `{completed, stopped} × Condition` is owned by [2.2](2.2-phase-execution.md); these are the
flow actions that drive it:

### `flow.complete` — early successful return

Ends the run successfully from anywhere in the graph; the run's result is Complete's input (`Complete(activation,
output) any`). The natural end — the final unit executing — needs no marker.

### `flow.degraded` — absorb and continue

A gate on its input. Placed inside a unit's **error action** (a `*Subgraph` the executor **must** run on failure), a
`flow.Degraded` node absorbs the failure into `completed × degraded`-bound continuation — successes kept, failure
recorded, no unwind. This is continue-on-error semantics: dependents are not pre-pruned; a downstream unit that needs
a failed output fails on its own when it runs, then its *own* error action degrades or escalates. Choosing
`flow.Degraded` over letting the failure escalate is the author's continue-vs-halt call.

### `flow.failed` — assert failure

Formats a failure message and asserts it; the transition policy adjudicates the stop ([2.2](2.2-phase-execution.md),
[2.6](2.6-execution-policies.md)). This replaced the pre-`op` `Fatal` action — a policy-driven stop, not an
unconditional halt.

## Variables and Iteration Values

The pre-`op` `SlotProxy` / `GatherRef` machinery is gone. Iteration values flow through the **variable frame**: each
gather dispatch mints a per-iteration frame binding `item`; bodies read it as a `VariableBinding`
(`plan.variable("item")`), optionally projecting one field of a record value at resolve time
(`plan.item("field")` → `VariableBinding{Name, Field}`; step 45). Subgraph scopes inherit frames — the same
mechanism that gives each subgraph its variable scope gives gather its per-iteration isolation
([2.1](2.1-typed-slots.md) owns the binding model).

## Lifecycle Hooks

`pkg/op/hooks.go`: `LifecycleHook` (`OnNodeStart` / `OnNodeComplete` / `OnSubgraphStart` / `OnSubgraphComplete`) with
a nil-safe `HookRegistry`, fired from node and subgraph dispatch. Hooks are fire-and-forget — a panic is recovered,
never failing the unit — and run synchronously; they must not block. The hook seam is the shared emission point for
the observability surface (event streams + narration, [2.8](2.8-eventing-infrastructure.md)); reconciling the
interface with its spec (run-status-transition callbacks) and feeding the event stream from it is phase-8 step 50.

## Serialization

Nothing here has bespoke serialization anymore. Graphs serialize as the graph document
([2](2-execution-graph.md)); execution — including every combinator's stamped nested stack — serializes on the trace
([2.2](2.2-phase-execution.md), [5.2](5.2-recovery-serialization.md)). The pre-`op` "PredicateFunc doesn't
serialize" caveat dissolved: a `wait_until` body is a subgraph, and subgraphs serialize.
