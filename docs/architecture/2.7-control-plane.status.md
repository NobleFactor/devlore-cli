## Completion

- [x] Model settled — one channel, two directions (commands in / events out), on the **Cassandra native protocol**
  shape (stream-id request/response **plus** unsolicited `REGISTER` → `EVENT` push), distinct from a pure
  request/response RPC.
- [x] Async API settled — `Request(cmd) <-chan ControlResponse` (the channel is the future / stream-id) and
  `Subscribe() (<-chan ControlEvent, cancel)` (bounded buffer, drop-oldest + gap signal). No blocking calls; the
  consumer's `select` loop is the event loop. Per-request response channels sidestep response head-of-line blocking;
  ordering is kept only for the inbound command sequence at the control-point.
- [x] Command semantics settled — `Pause` (preserve, `ErrPaused`, `PhasePaused`, resumable) vs `Stop` (unwind,
  `ErrStopped`, `PhaseStopped`, terminal, not resumable); `Step` later. The pause-flag becomes a control-point
  `switch`.
- [x] Ownership settled — on the `GraphExecutor`, shared to child executors via `newChildExecutor`; the per-run
  context-object taxonomy (context / world / plane / activation) recorded.
- [x] Transport settled — **HTTP/2 (gRPC)**, a swappable listener layer; HTTP/3 rejected (no native Go stdlib support;
  a control channel wants HTTP/2's ordered multiplexing anyway). curl-facing surface is REST commands + SSE events;
  gRPC is the typed equivalent over the same connection.
- [x] Message reference settled — request `{command, request_id?, count?}`, response `{status | error, request_id?}`,
  event SSE frame `{seq, <kind>, …}`; `command` the only required request field, `request_id` an optional client
  correlation token, `seq` a per-run monotonic gap-detector on every event.
- [x] Connection model settled — the plane is addressed by **run id**, not by connection/session, so events and
  commands are independent across the **same or different** connections (HTTP/2 multiplexes them on one; run-id
  addressing lets them split). A deliberate divergence from Cassandra's per-connection `REGISTER`; the listener is a
  stateless run-id → plane router.
- [x] **Slice A — the in-process async plane (landed 2026-07-20).** `pkg/op/control_plane.go` (`Request`/`Subscribe`
  + executor-side `poll`/`emit`, `Seq`-stamped, non-blocking throughout); `GraphExecutor` `pauseRequested → control
  *ControlPlane`; `controlPoint()` switch (`ControlPause` → `ErrPaused`, `ControlStop` → `ErrStopped`); Run's
  `ErrStopped` branch unwinds and lands the deliberate-halt terminal `stopped × healthy × stopped` (a clean stop is
  not a failure — settled here, distinct from the `execution_failed` failure terminal); `Pause`/`Stop`/`Control`;
  shared to children. Tests green (98 packages). Wire (Slice B) and narrator migration (Slice C) pending.
- [x] **Slice B — the HTTP/2 wire listener (landed 2026-07-20).** `pkg/op/server` — a run-id → plane router
  (`Router.Register`) serving `POST /v1/runs/{id}/commands` (request/response ack, terminal-run `409` guard),
  `GET /v1/runs/{id}/events` (SSE push, `seq`-carrying frames), and `GET /v1/runs/{id}` (status poll), over cleartext
  HTTP/2 (`h2c`) so one connection multiplexes the SSE stream and command POSTs as independent streams. The 2.7 curl
  examples are executable. Tests: handler guards + SSE-frame shape + a real-run integration (subscribe, pause mid-run,
  observe the ack and the pushed event). gRPC-equivalent surface + TLS/auth are follow-ons.
- [ ] **Slice C — reframed 2026-07-21 and moved to [step 50](../plans/extract-starlark-from-op/phase-8/steps/50-eventstream-narration-integration.md).** An integration, not a migration: `Status` (`status.Narrator`) and `Result`
  (`result.Pipeline`) do **not** move onto the plane. The steer-and-observe surface is **three orthogonal pieces** —
  control commands, event streams, narration — sharing the [`pkg/op/hooks.go`](../../pkg/op/hooks.go) hook seam; see the
  architecture doc's [Framing](2.7-control-plane.md#framing-three-orthogonal-pieces). The work: split the event stream
  off the command surface, build it on
  [`6-execution-topology.md` §Telemetry](6-execution-topology.md#telemetry-asynchronous-event-pipeline), feed it from a
  `LifecycleHook` (reconciling the `OnSubgraph*`-vs-spec-`OnPhase*` drift and retiring Slice A's inline `emit` calls),
  and leave narration orthogonal.

- [x] **The broker ruled (2026-10-21).** A pool of command-runner daemons and a broker that unifies eventing, telemetry
  and the command runner; HTTP/2 kept against HTTP/3 with three reasons; narration becomes a wire channel; outputs
  join as a fourth thing, a result. Recorded in [§ Ruled 2026-10-21](2.7-control-plane.md#ruled-2026-10-21-the-broker).
- [ ] **The runner selector** — the `account → runner session` plug point and its four policies. Designed; not built.
- [ ] **Dispatch and the fork** — `POST /v1/exec`; one frame stream per exec from the runner as the response body of the
  broker's `POST /exec`; the switch on the tag into the bus and the console. Designed as a sequence; not built.
- [ ] **The two streams** — `/events` and `/console`, one `seq` each, SSE `id:` as the resume point, a memory ring over
  an append-only file per stream, the octet-stream endpoint for bulk output. Designed; not built. Slice B's `/events`
  is the first of the two.
- [ ] **Authorization at the socket** — the peer's uid, the broker's own profile as the policy, a named refusal.
  Designed; depends on [`6.1-authorization.md`](6.1-authorization.md) and the [`authz` provider](https://github.com/NobleFactor/devlore-cli/issues/1116).
- [ ] **The remote leg** — the same API over TLS with a token; replaces [`6`](6-execution-topology.md)'s SSH transfer.
  Designed; not built. The direct, unbrokered path likewise.
- [ ] **The iterations** — the implementation is a schedule of four, filed after the specification merges: the `authz`
  and command providers against an in-process stub of this interface; the broker remoted; the runner plugged in; the
  bus plugged in ([plan § What follows](../plans/chore/1119-broker-specification.md#what-follows-the-specs-stay-in-front-and-the-iterations-become-a-schedule)).

## Outstanding / open questions

- **Fifteen named in [§ Open](2.7-control-plane.md#open), 2026-10-21** — command runner or graph executor first among
  them, since it decides the broker's size. None is settled by this revision; each is recorded in the form the owner
  rules from.
- **h2c** — Slice B listens cleartext HTTP/2 with prior knowledge on the local socket, which is the local leg the
  broker needs; the deprecation and the `http.Server` it waits on are [#689](https://github.com/NobleFactor/devlore-cli/issues/689),
  now under #1118.

- **Provider-access mechanism for the `Status` / `Result` migration — dissolved 2026-07-21.** The migration is retired
  (see the [Framing](2.7-control-plane.md#framing-three-orthogonal-pieces)): with three orthogonal pieces, providers keep
  narrating via `p.RuntimeEnvironment().Status` unchanged, and the event stream is fed from the
  [`pkg/op/hooks.go`](../../pkg/op/hooks.go) seam rather than from a provider reaching the executor — so no `activation`
  accessor is needed.
- **Event backpressure policy.** Drop-oldest + gap signal is the working default; confirm against a real slow-consumer
  scenario when the wire listener lands.
- **Wire surface details.** Run-id addressing landed in Slice B; auth is now [§ Authorization at the
  socket](2.7-control-plane.md#authorization-at-the-socket); hand-written REST facade versus grpc-gateway transcoding
  is still open, with the gRPC twin itself question 12 of § Open.
