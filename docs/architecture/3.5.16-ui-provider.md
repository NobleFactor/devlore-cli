## Thesis

The ui provider (`pkg/op/provider/ui`, `op.RoleModule`) exposes the runtime
environment's narration capability (`status.Narrator`) to Starlark: six methods, each a **thin passthrough** to
`p.RuntimeEnvironment().Status.<Method>(msg)`. The provider carries no state — configuration (sink, program name,
color, silence) lives on the narrator instance the client installed at bootstrap, so `--silent`, color, and
program-name prefixing apply **uniformly** across cli emissions, provider emissions, and Starlark output.

This is the **narration** piece of the run's observability surface
([2.8 §the three output streams](2.8-eventing-infrastructure.md)): human-facing status to stderr, orthogonal to
event streams and control. Under the step-50 integration, these emission sites stay exactly as they are — narration
is wired *to* the observability surface, never moved into it.

## API surface

```go
func (p *Provider) Note(msg string)          // ui.note(msg)    — informational (gray)
func (p *Provider) Warn(msg string)          // ui.warn(msg)
func (p *Provider) Error(msg string)         // ui.error(msg)   — non-fatal error
func (p *Provider) Succeed(msg string)       // ui.succeed(msg) — positive resolution
func (p *Provider) Fail(msg string) error    // ui.fail(msg)    — emits AND returns a wrapping error
func (p *Provider) Print(msg string)         // ui.print(msg)   — raw, undecorated
```

`Fail` is the one with a return: it emits the fatal-form message and hands back a non-nil error the caller
typically returns to abort.
