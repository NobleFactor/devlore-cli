## Thesis

The ui provider (`pkg/op/provider/ui`, `op.RoleModule|op.RoleAction`) exposes the runtime
environment's narration capability (`status.Narrator`) to Starlark: six methods, each a **thin passthrough** to
`p.RuntimeEnvironment().Status.<Method>(msg)`. The provider carries no state — configuration (sink, program name,
color, silence) lives on the narrator instance the client installed at bootstrap, so `--silent`, color, and
program-name prefixing apply **uniformly** across cli emissions, provider emissions, and Starlark output.

This is the **narration** piece of the run's observability surface
([2.8 §the three output streams](2.8-eventing-infrastructure.md)): human-facing status to stderr, orthogonal to
event streams and control. Under the step-50 integration, these emission sites stay exactly as they are — narration
is wired *to* the observability surface, never moved into it.

## API surface

```go
func (p *Provider) Note(msg string)          // ui.note(msg)    — informational (gray)
func (p *Provider) Warn(msg string)          // ui.warn(msg)
func (p *Provider) Error(msg string)         // ui.error(msg)   — non-fatal error
func (p *Provider) Succeed(msg string)       // ui.succeed(msg) — positive resolution
func (p *Provider) Fail(msg string) error    // ui.fail(msg)    — emits AND returns a wrapping error
func (p *Provider) Print(msg string)         // ui.print(msg)   — raw, undecorated
```

`Fail` is the one with a return: it emits the fatal-form message and hands back a non-nil error the caller
typically returns to abort.

## Root placement: owning `print` and `fail`

> Designed 2026-08-26 under [#698](https://github.com/NobleFactor/devlore-cli/issues/698); see
> [`docs/plans/ui-at-root.md`](../plans/ui-at-root.md). Not yet landed.

Starlark ships exactly two output builtins — `print` and `fail` — and devlore owns neither. A script's `print`
resolves to `starlark.Universe`, is formatted by the interpreter, and is written straight to stderr by
`starlark-go`'s default. It never reaches the narrator, so it escapes `--silent`, escapes color and
program-name prefixing, and would escape the diagnostics stream of
[2.8](2.8-eventing-infrastructure.md). That is a hole in the uniformity the Thesis claims.

Adding `op.RoleRoot` closes it with no new mechanism. Starlark's resolver checks **predeclared before
universal**, and `CamelToSnake` maps `Print`→`print` and `Fail`→`fail`, so installing the methods as
top-level predeclared entries *replaces* the builtins — no `starlark.Universe` mutation, no `Thread.Print`
hook, no interception code.

| Global | Method | | Global | Method |
| --- | --- | --- | --- | --- |
| `error` | `ui.Error` | | `print` | `ui.Print` |
| `fail` | `ui.Fail` | | `succeed` | `ui.Succeed` |
| `note` | `ui.Note` | | `warn` | `ui.Warn` |

Root placement **replaces** the provider global rather than adding to it: `placeModule` installs each method
as its own predeclared entry and never sets `predeclared["ui"]`. `ui.note(...)` stops resolving.

`error` claims a word a script might want as a variable, and a predeclared name cannot be assigned over at
module scope — `error = compute()` is a resolve error, not a shadow. Accepted: authors use `err`, the same
convention Go authors follow because the language took `error` first.

## Why the signature is `(msg string)`

The builtin is `print(*args, sep=" ")` — variadic, keyword separator, any value type. These methods are
narrower on all three axes, and that is **deliberate**, not a gap to close later. Two ways of widening them
were considered and both are wrong:

**`fmt.Printf` semantics double-interpret the string.** Starlark's `%` is an operator (`interpolate`, in
`starlark/eval.go`) that runs *before* the call, so `print("%s" % name)` arrives as a finished string. Printf
semantics would re-scan that string for verbs, turning `50% off` into `50%!o(MISSING)ff` whenever the data
contains a `%`. Go avoids this by making `Print` and `Printf` different functions; one function cannot be
both. The everyday form of the same defect is `print("100% done")`.

**Variadic space-join arrives too late to render correctly.** `fillVariadicSlot` runs `toGoInto` before
dispatch, so a Go-side `args ...any` receives Go natives: `True` as `bool`, `None` as `nil`, a list as
`[]any`. Rendering those Go-side yields `true`, `<nil>`, `[a b]` where Starlark says `True`, `None`, `["a"]`.
Faithful output would mean reimplementing `writeValue` on the far side of a conversion that already discarded
the information it needs.

**One string is therefore the correct contract.** The script renders with `str()` and `%` — Starlark's own
rendering, deterministic by construction — and hands the provider a finished string. For a configuration
language, requiring an explicit `str()` is a feature: nothing is stringified by a rule the author cannot see.

The tree already works this way without exception. Every call site was surveyed on 2026-08-26:

| | Call sites | Multi-argument | Non-string argument |
| --- | --- | --- | --- |
| `print(` | 64 | 0 | 0 |
| `fail(` | 65 | 0 | 0 |

Each passes a single string built with `%`, `+`, or an explicit `str(...)`.

**Residual cost, stated rather than hidden.** `print("a", "b")` and `print(42)` are legal against the builtin
and are errors against these methods. Nothing in the tree does either, but a Python reflex produces one. The
errors are legible: `toGoScalar` uses `starlark.AsString` with no coercion, so `print(42)` reports `expected
string, got int`, and a multi-argument call reports an arity error.
