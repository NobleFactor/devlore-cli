## Discrepancies (design vs. current code)

Inventoried 2026-10-21 against develop `4992f580`.

- `pkg/op/provider/elevator` exists: `provider.go`, `broker.go`, `config.go`; a package doc calling everything
  provisional; `Elevate` / `CompensateElevate` without the activation record, returning `errNotImplemented`; a concrete
  `Broker` struct with a working `RegisterDriver` and stub `InitializeFromConfig` / `RequestElevation`; config types
  not on `devconfig`. No importers; no `gen/`; not announced. Dead by ruling; removed by #679.
- `op.ElevationOffer` (`pkg/op/elevation_policy.go`): a string-enum strategy with `HostEscalation`,
  `InteractiveChallenge`, `IdentityAssumption`, `MandatedApproval`; `WithElevationOffer` on every spec, applied at
  construction, **called by nothing**; `ElevationOffer()` **read by nothing**; not serialized; `starlarkbridge` skips
  "`elevation` while it stays dormant".
- `flow.Provider` has no `Elevate`; `pkg/platform`'s spawner is `runCommand(argv, sudo bool)`, a package var, with
  every privileged call site passing a literal `true`; `NeedsSudo()` is declared and implemented and called by nothing;
  Windows elevates with `Start-Process -Verb RunAs`.
- No `authz` package, no `Authorize` action, no `offer_reference_id` on any node, no offer check in `ValidateGraph` or
  the run preflight, no `providers.authz` section; `pkg/devconfig` is the flat section map, and no provider package
  uses it.
- `cmd/writ` has no elevation of any kind: `BuildGraphs` builds one graph per scope, the System root is `/`, and a
  System tree deploys only if writ itself runs as root (David-Noble-at-work/personal#289).
