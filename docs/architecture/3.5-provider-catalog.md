## Purpose

Each provider owns a Starlark namespace (`file.*`, `archive.*`, `git.*`, …) and contributes a set of actions or a
resource scheme to the execution graph. This catalog is the **index of record** for which providers exist, the namespace
each owns, its access role zone, and — where one has been written — a link to its dedicated design document. New
providers are added here as a row; providers substantial enough to warrant a full design doc get a numbered `3.5.x`
sub-document.

## Surface eligibility

A provider declares which surfaces it is eligible for; which of its METHODS reach a given runtime is decided
per runtime from their claims (see [3.6-method-classification.md](3.6-method-classification.md)).

- **module + action** — the default. Eligible for the graph and for a runtime's module surface.
- **action** — graph only. `flow`, whose methods *are* the graph combinators and mean nothing outside one.
- **module** — module surface only. `plan`, there being no scenario for planning the planner.

The Role column below is the announced value, not a directive: it is `ProviderRole`'s dispatch zone as emitted
into each provider's `gen/provider.gen.go`. The Claims column counts the methods carrying each claim, which is
what a hermetic runtime filters on — a provider with none contributes nothing to a planning surface and reaches
a script through `plan.<provider>.<method>` instead.
