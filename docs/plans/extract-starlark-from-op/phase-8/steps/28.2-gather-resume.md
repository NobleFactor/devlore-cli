# Sub-step 28.2 — Gather resume (stamped `RecoveryStack` + delegate-to-Subgraph)

**Status:** design settled 2026-07-01 — awaiting implementation
**Parent:** [28-subgraph-executor-ownership.md](28-subgraph-executor-ownership.md)

## Finding — the signature collapse already landed; the work is resume

`flow.Gather` already returns a single `*op.RecoveryStack` and `CompensateGather` already takes one — no
`[]*op.RecoveryStack` remains anywhere. The slice→single-stack fold is done. What is broken is **resume**: `Gather`
mints throwaway `op.NewRecoveryStack()` roots and never reads `activation.Stack`, so on resume the child stack the
framework adopts is discarded and every iteration re-runs; and the nested substacks are anonymous (`PushNested`), so
there is no per-iteration key to skip on.

## The shape — one recursive rule

**Subgraph is the base case of its own family.** Choose / Gather / WaitUntil are *quantifiers* over Subgraph: each runs
one body-subgraph K times and nests the K results. The only thing that varies is K and the condition that governs it:

- **Subgraph** — runs its body once (K = 1). The base case.
- **Choose** — runs the one branch the graph already selected (K = 1). `ChoosePlanner` builds the branches into the
  graph; the graph selects; Choose *receives* the result — it does not select at runtime.
- **Gather** — runs the body once per item (K = N, sequential or parallel).
- **WaitUntil** — runs the body until truthy or timeout (K = 1+).

Each body-run yields **one stamped `RecoveryStack`**; the combinator's complement is the parent stack holding the K
stamped sub-stacks. Resume walks them by stamp.

## The stamped `RecoveryStack` — identity on the stack, *not* a receipt

A `RecoveryStack` gains the receipt's outcome/identity **subset as its own fields**: `unitID` (the resumption key),
`result` + `resultType` (cached output + retype-on-resume fidelity), and `err`/status (done vs paused). It does **not**
embed `ReceiptBase` / implement `Receipt`:

- `ReceiptBase` carries ~8 fields meaningless for a stack — `resource`, `compensatingAction`, `transactionID`, `slots`,
  `annotations`, `attempts`, `complement`. The `Receipt` contract is "carries the affected `Resource`, the moment
  issued, and a `transactionID` correlating the forward call with its reversal"; a stack has none of those.
- Compensation semantics differ. A receipt compensates via a **named companion** (`compensatingAction` → registry →
  provider method); a stack compensates via its **intrinsic** `Unwind`. Embedding would force the stack through the
  companion-lookup path — `Push` would have to special-case it.
- The clean framing: **a receipt is "identity + a separate undo"; a stamped stack is "identity + I am my own undo."**

If a single lookup over both kinds is ever needed, factor a small accessor interface (`UnitID() string; Result() any;
Err() error`) that both `ReceiptBase` and `RecoveryStack` satisfy — not the sealed `Receipt`. The stamp fits the
setter-free rule: `unitID` is known at creation (set it there); `result`/status at completion (a one-shot finalize — the
`receipt.Commit` analog, not a piecemeal setter). Add `forwardAction` to the stamp only if the stamp is unified with the
subgraph audit receipt, so `Trace.Summarize` still tallies combinator dispatches.

## Delegate to Subgraph

Choose / Gather / WaitUntil call **`flow.Provider.Subgraph` K times**, each with a fresh child stack and a per-run
frame, and nest the K returned stamped stacks. `walkSubgraphChildren` becomes Subgraph's private implementation — only
Subgraph calls it; the combinators call Subgraph.

- **Delegate to the method (which *returns* its stamped stack), not the framework dispatch that *pushes* onto the
  parent.** For parallel Gather this is the concurrency invariant we already settled: each goroutine runs the body on its
  **own** stack and gets the stamped stack back; the **main goroutine** nests the N results in index order, so the shared
  `activation.Stack` stays single-writer.
- **No planner change is forced.** Gather reuses its own `*op.Subgraph` unit as the body — it builds a per-iteration
  activation (fresh stack + iteration frame, same `Unit`) and calls `p.Subgraph(...)`.
- The combinator owns only what is combinator-specific: **K**, the **stop condition**, and the **per-run index** stamped
  onto each sub-stack's `unitID`.

## Resume

Each body-run's stamped stack is its resumption point (a paused gather has N of them, one per item). Gather re-runs;
for run `i`, `activation.Stack.nestedStackByUnitID("<gatherID>#<i>")`:

- found, `err == nil` → skip; return the stamped `result`.
- found, paused → adopt the sub-stack and re-enter Subgraph on it (the body's own child skip-guards finish it).
- absent → fresh run.

No synthetic receipts, no positional mapping — the stamp is the key, mirroring `subgraph.Execute`'s adopt-guard
(`receiptByUnitID` → the nested-stack analog).

## Serialization

The `{"sub": {...}}` nested form gains `unit_id` / `result` / `result_type` / `status` on the sub-stack; it round-trips
through the existing recursive decode, and the reloaded (untyped) `result` retypes via `result_type` exactly as a
receipt's does.

## Scope and generalization

Gather-first. The same shape covers Choose (K = 1) and WaitUntil (K = 1+). It generalizes further: a stamped stack could
**subsume the combinator audit receipts** entirely — a structural dispatch becomes a stamped stack (identity + I am my
own undo) rather than a receipt whose complement is a stack. Resource/leaf dispatches keep receipts (their undo is a
genuinely separate complement). Whether to unify subgraph now or leave its audit receipt in place is the one open scope
call; the gather work does not depend on unifying it.
